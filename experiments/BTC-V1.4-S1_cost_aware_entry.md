# V1.4-S1 — Cost-aware entry gate
User chose decision optimization only; native fee deduction not requested. Previous native fixed-cost pilot run 44876269047 cancelled. The new strategy is independent; unchanged V1.4-A is the control.
## Hypothesis and implementation
After EMA20/50 crossover, EMA200 trend and ADX14 > 25, compute ATR14 from completed hourly bars and use current observed midpoint P (or unchanged fallback quote). Estimated extra single-side slippage s = 0.0001 + 0.02 ATR/P, assumed single-side fee f = 0.0005. Estimated round-trip friction per BTC C = 2(f+s)P. Admit entry only if C/ATR <= 0.20. These are hypothetical rates, not observed fees or slippage. ATR is a volatility proxy, not expected profit. Algebraically this gate is equivalent to ATR/P >= 0.0075, so it is also a minimum relative volatility filter; any improvement is not evidence of accurate cost prediction. No extra market-data calls. Invalid input skips entry. Log COST_ENTRY_CHECK with price, ATR, assumed fee, estimated slip, round-trip cost, ratio, threshold, decision. No delayed entry after rejection. Retain risk budget 0.5%, allocation cap 50%, 95% cash cap, 3 ATR stop anchored to confirmed fill, EMA death-cross exits, market orders, long/flat only. No change to sizing or exit behavior.
