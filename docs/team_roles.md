# 三人分工与交付清单

A/B/C 是角色标记，实际成员待团队填写。每项任务只有一个负责人；负责人完成研究、计算、必要实验、记录和正文。不设置复核人或审批步骤，任务完成条件由负责人自行检查。

## A：策略设计、完整代码、执行摘要与实现细节（35 分）

| 任务 | 要做什么 | 必交成果 | 前置输入 |
| --- | --- | --- | --- |
| A01 | 测试 API、行情周期、订单、数量单位及盈亏 | 技术能力记录、最小开平仓记录 | 课程账户 |
| A02 | 提出交易假设，确定工具与输入 | strategy_spec.md 第 1—3 节、方法来源 | C01 平台清单 |
| A03 | 明确指标、公式、交易条件、退出及异常行为 | 完整策略规格 | B01/B02 风险资金规则 |
| A04 | 实现交易、仓位、订单状态与风控 | src/ 中完整脚本、配置 | A03、B01/B02 |
| A05 | 自行检查指标、数量、时间与订单，修复错误 | 技术试验记录及对应代码版本 | A04 |
| A06 | 根据登记实验修改实现，保存每次准确版本 | 代码提交、变更原因 | C 的实验设置 |
| A07 | 写实现细节；最后根据结果写摘要 | report/01、02 两份完整章节 | 最终结果及 B/C 结论 |

A 负责代码实现，不独自决定风险预算或按最终测试表现调参。风险政策由 B 给定，正式比较实验由 C 登记执行。

## B：风险管理与资金管理（35 分）

| 任务 | 要做什么 | 必交成果 | 前置输入 |
| --- | --- | --- | --- |
| B01 | 识别风险，确定止损、敞口、暂停和恢复规则 | risk_capital_spec.md 风险规格 | A 的基础信号、合约信息 |
| B02 | 定义数量换算、现金、保证金、资金缓冲 | 仓位公式和可计算示例 | 合约乘数、数量步长、账户字段 |
| B03 | 提出跳空、连亏、成本、集中与故障场景 | 风险实验清单及所需字段 | B01/B02 |
| B04 | 用 C 提供的输出计算情景损失及风险效果 | 风险结果表、假设与限制 | 已登记实验结果 |
| B05 | 计算最低资金、合理规模、资金利用、容量 | 资金及容量分析表 | 持仓、敞口、保证金和流动性证据 |
| B06 | 写风险、资金两章，回答 R01—R03、K01—K05 | report/03、04 两份完整章节 | B01—B05 |

B 自己完成风险资金分析，不能只给 A 一句“控制仓位”。规则必须在正式策略回测前交给 A；未实现控制与已实现控制分开标注。B 计算的规模、杠杆及资金结果交给 C，用于实盘预期。

## C：回测表现、实盘预期与报告整合（30 分）

| 任务 | 要做什么 | 必交成果 | 前置输入 |
| --- | --- | --- | --- |
| C01 | 确认课程数据、权限、成本设置及输出能力，检查数据质量 | platform_capabilities.md、数据说明 | A 提供接口试验、B 提供资金字段需求 |
| C02 | 规定样本用途、指标、实验比较及参数选择办法 | 实验计划、experiment_log.csv | A/B 规格 |
| C03 | 指定并记录每次运行，保存 ID、代码版本、配置及输出 | 可追溯实验包 | 可运行脚本与配置 |
| C04 | 计算收益和交易指标，制作净值、回撤、月度及年度图表 | 分析程序、表格和图表 | 回测输出 |
| C05 | 查询市场背景和具体经纪商条件，分析实盘限制 | 实盘证据与来源 | A 的实际功能、B 的资金结论 |
| C06 | 写回测及实盘章节，维护问题覆盖状态 | report/05、06 两份完整章节 | C01—C05 |
| C07 | 合并各人完整章节、统一格式、整理两项提交 | 报告、脚本包及受限提交凭证 | A/B 各自完成的正文 |

C 不是替 A/B 写报告的人。只有取得逐日或逐笔数据才计算相应指标；无法取得时明确限制，不补造数据。C 作为正式实验默认操作人；如因平台权限由 A 操作，仍由 C 登记设置、版本及输出位置。

## 顺序与交接

1. A 测接口，B 查资金条件，C 汇总平台及数据能力。
2. A 写基础信号，B 写风险与仓位，C 写实验设计。
3. A 合成完整程序，B 提供具体风险场景，C 保存技术运行结果。
4. C 执行开发/验证实验，A 处理实现改动，B 完成风险资金分析。
5. A 冻结代码，B 冻结风险资金政策，C 冻结配置并运行最终测试。
6. A/B/C 写自己的章节，C 整合报告并操作课程提交。

每次交接必须写明：任务 ID、成果位置、使用版本、已完成内容、未确定事项、下一步需要的输入。每天更新进展；每两至三天讨论规则变化并记录决定。群聊只用于协调，正式结论存档。

每项工作完成须有具体文件或输出，不能仅以“讨论过”标记完成。不设置他人批准条件；各负责人自行确认计算和实现正确。
