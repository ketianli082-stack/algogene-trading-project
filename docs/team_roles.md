# 三人分工与交接规范

## 1. 角色与责任

成员实际姓名及账号由团队后续确认，本文仅使用 A/B/C。

### A：策略与平台负责人

- 核查 ALGOGENE API、合约单位、订单机制和运行环境。
- 将共同确定的假设写成公式、参数和边界条件。
- 维护正式策略代码、订单状态、仓位和风险控制。
- 保存每次正式运行的代码及配置，记录平台回测 ID。
- 撰写实现细节，提供已实施风险控制的说明。
- 核对最终提交脚本与回测对应。

### B：数据与验证负责人

- 检查数据覆盖、字段、时区、异常、复权与聚合规则。
- 核查交易成本、信号与成交时间、合约和汇率换算。
- 独立复核指标和若干交易，检查重复下单及信息泄漏。
- 维护实验登记，计算收益、回撤、交易指标和稳健性。
- 完成成本及执行压力分析，撰写回测表现。
- 监督最终测试区间使用，避免事后调参未披露。

### C：研究与交付负责人

- 维护任务、日程、研究决定及报告证据索引。
- 整理方法引用、市场背景，区分证据和推断。
- 计算最低资金、保证金、合理规模和容量假设。
- 统一图表与报告，撰写资金管理、实盘预期和摘要。
- 组织交叉核对与提交；不将未验证方案写成已实现结果。

## 2. 交叉复核

| 成果 | 主责 | 复核 | 验收重点 |
| --- | --- | --- | --- |
| 策略规格及代码 | A | B | 窗口、时间、数量、状态和风控 |
| 数据与成本说明 | B | A | 字段与实际实现一致 |
| 绩效与图表 | B | C | 公式、区间、来源、正文一致 |
| 资金与容量 | C | A | 乘数、保证金、敞口和可执行性 |
| 报告整合 | C | A、B | 方法、数字、结论和限制 |
| 最终提交 | 指定一人 | 另一人现场核对 | 文件、ID、版本及确认信息 |

每人应能解释整套策略。风险管理由 A 提供控制实现、B 提供测试证据、C 整合论证，不由单人凭一般描述完成。

## 3. 实验交接

1. 提出问题并登记实验，注明开发/验证/最终测试角色。
2. A、B 核对设置；指定一人运行，避免多人覆盖正式策略。
3. 运行者保存代码提交编号、配置、回测 ID 和完整输出。
4. B 独立检查；失败、异常或放弃的试验同样保留。
5. 形成发现、证据与局限；C 将通过复核内容写入报告。

交接信息必须包含：实验 ID、目的、唯一变化、区间、代码版本、结果位置、待复核事项与下一负责人。

## 4. 沟通与决策

- 每日异步更新：已完成及链接、下一步、阻碍、需要谁何时提供什么。
- 每两至三天召开 20—30 分钟会议，处理规则变更、异常、候选选择和版本冻结。
- 群聊用于协调；正式决定写入 decisions.md，代码问题写入 Issue，报告意见写在共同文档评论中。
- 改变交易规则、品种、成本、风险预算或测试用途，需要记录原因及受影响实验。
- 无人单独依据 2025 年结果调参后仍将其称作独立测试。

## 5. 最终核对

A 打开最终代码配置，B 打开回测及指标，C 打开报告逐项核对。通过后以 v1.0-submission 等固定标记对应提交。实际操作人、复核人和提交凭证记录在团队受限空间；公开文件不填写学生编号及敏感账户信息。
