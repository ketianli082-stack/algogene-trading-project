# 三条研究工作线与三人交付清单

A/B/C 为角色，实际成员待分配。按信号研究、风险资金研究、回测与实盘研究分工；每人完成自己的研究、程序或计算、实验与正文。不单设只统筹或写报告的人，不设置复核人或他人审批。

报告分值不是工作量的度量。A 有整合负担，因此 B 必须交付可接入模块，C 必须承担结果获取与分析工具；第一版限制工具、参数和模块数量。

## A：什么时候买卖——信号研究与交易核心

负责报告：执行摘要（15 分）、实现细节（20 分）。摘要最后依据全部结果完成，技术整合不等于代做其他研究。

| ID | 具体任务 | 交付物 |
| --- | --- | --- |
| A01 | 测试行情、历史查询、账户字段、数量和订单接口 | 最小开平仓及接口行为记录 |
| A02 | 结合 C 的数据条件确定工具、输入、假设及方法来源 | 策略规格第 1—3 节 |
| A03 | 定义指标、信号、入场及市场信号退出 | 精确公式、参数、执行时点和边界条件 |
| A04 | 编写行情处理、信号、订单与持仓状态核心 | src/ 下交易核心代码 |
| A05 | 接入 B 的仓位风控模块及 C 的结果记录需求 | 可运行完整脚本、配置及版本 |
| A06 | 自行检查交易行为，完成信号及少量参数实验 | 技术记录、信号实验及解释 |
| A07 | 写实现细节；最终写摘要 | report/01、02 完整正文 |

A 负责平台调用和最终整合，不替 B 编写全部风险规则，不替 C 计算全部绩效。信号实验由 A 设计、分析和解释，C 统一登记。

## B：买多少、怎样控制亏损——风险资金研究与模块

负责报告：风险管理（20 分）、资金管理（15 分）。

| ID | 具体任务 | 交付物 |
| --- | --- | --- |
| B01 | 识别风险，确定保护止损、敞口、暂停与恢复 | risk_capital_spec.md 具体规则 |
| B02 | 定义风险预算、数量、现金和保证金约束 | 仓位公式、合约换算及计算示例 |
| B03 | 编写仓位、风险控制函数或可嵌入代码段并自行检查 | src/risk/ 风险与仓位模块、输入输出说明 |
| B04 | 设计、分析仓位及止损对照、跳空和连亏场景 | 风险实验及分析结果 |
| B05 | 编写必要分析或完成可复算表格，计算资金、占用、规模及容量 | analysis/risk_capital/ 程序或计算表及结论 |
| B06 | 写风险资金两章，向 C 提供规模、杠杆与容量结论 | report/03、04 完整正文 |

B 在完整策略回测前将可接入模块交给 A，不只给文字要求。即使平台最终仅使用一份脚本，B 也提供函数或代码段，由 A 接入事件和订单流程。B 拥有风险实验，不把设计、分析全部交给 C。未实现控制明确单列。

## C：效果是否可信、现实能否执行——实验分析与实盘研究

负责报告：回测表现（20 分）、实盘预期（10 分），并统一格式和整理提交。

| ID | 具体任务 | 交付物 |
| --- | --- | --- |
| C01 | 查数据覆盖、质量、权限、成本和输出能力 | 平台能力表、数据说明 |
| C02 | 规定样本用途、基准、指标及统一实验记录 | 实验计划、登记和结果包规范 |
| C03 | 编写结果读取、绩效和图表程序，承担结果导出及整理 | analysis/performance/ 分析工具、输出接口需求 |
| C04 | 设计、分析基准、成本及执行延迟敏感性实验 | 自己负责的实验及绩效图表 |
| C05 | 研究市场背景、具体经纪商条件与实盘限制 | 有来源的实盘分析 |
| C06 | 写回测和实盘两章，维护老师问题状态 | report/05、06 完整正文 |
| C07 | 合并三人已完成章节，统一格式并整理提交 | 最终报告、脚本包与受限提交凭证 |

C 不是只点击运行、导出截图或排版。C 统一登记所有实验，但不代做 A 的信号实验或 B 的风险实验。缺少逐日/逐笔输出时说明限制，不能补造。

## 模块边界及交接

- A 决定基于市场信号的退出；B 决定保护性止损及账户风险退出。B 写明与 A 信号退出同时发生时的优先级，A 在订单层落实，避免重复平仓。
- B 的模块说明输入（权益、持仓、行情、ATR、合约、可用资金等实际需要字段）、输出（目标数量、风险动作及原因）、单位、调用时机和异常处理。A 负责获取平台字段、适配及发送订单。
- C 提供绩效所需输出字段；A 接入必要记录点，C 负责获取、整理和分析。平台输出不足时先测试可行方案并披露限制。
- B 给 C 资金规模、杠杆和容量；A 给 C 自动化及故障处理的真实边界。C 据此完成实盘分析。

## 谁负责实验

| 实验类别 | 设计、分析及解释负责人 | 共同规则 |
| --- | --- | --- |
| 信号规则和参数 | A | 使用统一配置、样本纪律和实验登记 |
| 仓位、止损、风险与资金 | B | 保存基线、变化、版本、输出和限制 |
| 基准、成本及执行敏感性 | C | 不根据最终测试反复选择参数 |

平台运行按账户权限安排，允许 A/B/C 各自操作，或由有权限的人代运行。研究归属不因点击者改变。C 统一登记设置、平台 ID 和输出位置，不承担全部实验分析。

## 并行推进与交付顺序

1. 三人确定一个基础方向；A 测接口并做最简单交易核心，B 同时做数量函数和资金示例，C 同时做数据说明及绩效工具。
2. B 交可接入模块和规则，C 交输出字段需求，A 完成整合。初期工具可使用明确标记的示例数据，示例不得进入最终结果。
3. 三人分别完成各自实验，采用统一设置和记录。错误及变更归档。
4. A 冻结核心和整合脚本，B 冻结风险模块，C 冻结实验配置并组织最终测试。
5. 每人写完自己的章节；C 整合与提交，不代写 A/B 内容。

每次交接注明任务/问题 ID、成果位置、版本、输入输出、已完成事项和待确定项。每日简短更新，每两至三天记录重要决定。

## 工作量与完成标准

A 的程序跑通不意味着 B/C 完成。B 还须交付风险资金计算及实验；C 还须交付绩效可信度与实盘研究。三人均有独立文件和证据。若 B/C 编程能力有限，应承担可独立完成的计算表和实验分析，提前协调实现范围，不能把全部技术工作默认留给 A。

完成以具体成果为准，各负责人自行检查；分值相近不保证耗时相同，若 A 的接口整合明显增加，应缩减初版复杂度并由 B/C 承担文档化、输出处理和可分离实现。
