状态：用户已确认两阶段流程；具体方向、工具、金额、风险上限、费用及搜索预算待今晚会议确定。本文件中的建议不是已经通过的团队决定。

## 1. 共同时间与样本

- 11 月 17 日 23:59（HKT）：每人提交基础版本；18 日展示。
- 2021—2023：开发，17 日前的收益比较使用此区间。
- 2024：保留验证；18 日先固定候选、比较规则和参数，再于 19—20 日运行。验证参与最终选择，不是独立最终证据。
- 2025：最终测试；不得提前跑三份方案后按该年选胜者。22 日冻结，23 日运行。
- 所有修改、试验及看到的数据用途记录；数据检查若已接触测试期，应描述范围，不据收益调参。

## 2. 今晚必须统一的条件

| 项目 | 要确定什么 | 当前状态 |
| --- | --- | --- |
| 账户及权限 | 各自账户或获准的课程环境、能否独立运行、最终提交身份 | 待确认，不共用密码 |
| 工具范围 | 尽量相同工具或共同许可清单；工具类型、数据和合约规格 | 待平台核查 |
| 初始资金 | 相同币种及金额；覆盖最小单位和保证金需求 | 待定，不能照抄 Live Test 净值 |
| 风险边界 | 敞口、杠杆或风险预算上限及资金缓冲 | 待定，不为追求收益放大仓位 |
| 费用 | 各工具合理佣金、点差、滑点、融资及已含项目 | 待定；工具差异可不同但须有来源 |
| 信号执行 | 完成数据生成信号后下一可执行时点，未知路径披露 | 待测试具体平台行为 |
| 指标 | 净累计收益、年化收益、日收益波动/Sharpe、回撤、交易数、持仓和敞口 | 统一定义及年化口径 |
| 搜索预算 | 每人事前约定有限规则/参数组合数量，完整登记 | 待会议填数 |
| 输出 | 代码、配置、ID、净值、交易、成本及异常；缺失处理 | 待测试导出或记录 |

收益比较必须同时看风险、敞口、费用和实际可执行性。相同初始资金不保证风险相同。不能仅用平台 Sharpe 数值跨工具排序，先确认口径一致。

## 3. 单人交付包

candidates/member_x/ 下保存 README.md（约两页说明）、strategy.py（实际实现后加入）、config.json、experiment_log.csv、results_summary.md。完整结果放受限空间，公开索引不含私人分享链接或账户身份。

必要内容：假设和来源；具体工具/输入；精确信号和执行；风险控制；数量和资金约束；代码及平台 ID；开发结果；净值回撤和交易统计；关键假设、异常和未完成研究。

每人按老师 28 题标记初步答案或待完成事项，数据不足不得虚构。容量、理想规模和经纪商支持可先明确问题及查证计划；最终报告仍须逐题回答。若无法运行，提交最小错误记录与替代方案并标记“不具备可比结果”，不以假设结果参与排名。

## 4. 18 日及验证期的选择程序

1. 每人展示 10 分钟，讨论 5 分钟，先说明机制、成本、风险及缺陷。
2. 排除存在未解决信息泄漏、数量错误、遗漏关键费用或不可执行设置的结果；允许修复并留痕。
3. 对照相同口径汇总开发结果、分年稳定性、参数邻域、成本敏感性及可解释性。
4. 形成最多一至两个候选，固定验证配置与选择顺序，不以最高总收益单独选定。
5. 19—20 日使用 2024 验证；记录收益、回撤、费用承受力、交易数和剩余实现工作，选择主方案并说明取舍。
6. 验证不支持时可保留最有研究价值的方案并披露失败，或在时间允许时修改；不能不断搜索后宣称验证未参与研究。
7. 指定 S/R/E，保留三份原始版本，集中迭代一份主策略。任何预先数值门槛及排序优先级今晚/18 日运行前写定。

## 5. 最终阶段

冻结工具、代码、参数、风险、资金、成本、预热及期初持仓后测试 2025。错误修复与重测披露。测试表现差不自动触发再调参，也不保证盈利。全部最终数字与报告及提交版本一致。
