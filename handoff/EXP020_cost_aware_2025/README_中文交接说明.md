## 2. 策略核心思想

**策略类型**：BTC / ETH 现货—期货价差均值回归，双腿对冲；不仅做多，也可做空；不是保证无风险的期现套利。

**交易标的**：`BTCUSD` (spot)、`BTCUSDM` (futures)、`ETHUSD` (spot)、`ETHUSDM` (futures)。

**周期**：ALGOGENE 只读取 **H1（60 分钟）** 历史，程序从连续且完整的 H1 数据自行合成 H4 信号与 H24 风险状态，禁止直接请求不被平台支持的 H4。

**交易依据**：计算 `basis=ln(futures_price/spot_price)`。最近 42 根历史 H4 的价差中位数作为中心，使用 MAD（不足时改用样本标准差）标准化最新已完成 H4 价差；当 `|z|>=2` 且距离中心的价差优势足够大时准备入场。

**方向**：
- `z>0`：期货相对贵 → **卖出期货、买入现货**；
- `z<0`：期货相对便宜 → **买入期货、卖出现货**。
注意源代码中 `side=-1 if z>0 else 1`，`_open()` 将现货方向设为 `-side`、期货设为 `side`。

**关键风控**：
- H24 日收益移动超 6% 或近两日绝对基差超 2.5% 时不入场；
- 当前绝对基差 >2.5% 不入场；当前与最近一根已完成 H1 的基差差 >0.6% 不入场；
- 当前任一腿相对已完成 H1 收盘跳变 >3% 不入场；
- 最近 5 个连续 H1 同时段的价差中，最大一小时跳变 >0.6% 或最近 4h 极差 >1.2% 不入场；
- 任一腿缺失时间戳/报价或 H4/H24 拼接存在断档，跳过该组交易，而不是强制补齐；
- 两腿美元名义金额相差 >1% 不入场；
- 全账户最大回撤阈值为 8%，触发后停止新开仓并退出已有仓位（按小时检查，不保证无间隙止损）；
- 双腿下单确认、失败救援平仓、超一小时待成交暂停均在代码中处理。

**仓位**：每组 gross pair 目标为净值的 10%，两条腿各约净值的 5%；仓位按合约乘数换算、向下保留 0.01 lots；无杠杆（原生 `Leverage=1`）。即使同一事件有多组信号，也只下单一组新配对。

**平仓**：小时快照下不利基差变化达到 0.0075，则 `BASIS_STOP`；或持有满 36h、到期强制平仓；若价差回到 H4 中心附近容差 `0.4*scale`，则 `H1_REVERT`。普通退出后冷却 18h，基差止损后冷却 48h。

## 3. 交易费用：最重要的限制

在原策略 `PARAMS` 中，`fee_rate=0.0005` 表示 **每一次实际成交的金额 × 0.05%**。计算公式：

```python
fee = fill_price * fill_volume * contract_size * 0.0005
```

`on_orderfeed()` 成功回调后才记费，包括**现货开仓、期货开仓、现货平仓、期货平仓**四个事件，且手续费是策略内部的虚拟账本 `fee_total`。下单前预计四次费用：

```python
estimated_4fill_fee = 2.0 * (ns + nf) * 0.0005
net_expected = min(ns, nf) * current_edge - estimated_4fill_fee
# 要求 net_expected >= 50 USD 才允许开仓
```

策略将累积影子手续费从用于仓位和风险控制的 NAV 中扣除，回测终点输出 `COST_FINAL`，但 **这并不能修改 ALGOGENE 服务器的 `TradeCost`。**

**平台实际没有接受零原生费用。**
- 原始回测提交：`TradeCost=0`。
- ALGOGENE 返回生效值：`TradeCost=1.0`（USD，每个开仓成交；平仓端记录 0）。
- 因此原生回测标记 `INVALID_REVIEW`；不要将原生评分标注为“0.05% 费用后的平台分数”，也不要说平台是零手续费。
- 原始 EXP-020 **没有**做平台固定费还原，因此其内部风险 NAV 基于平台已扣 $1 的账户 NAV，又扣影子 0.05% 费用，存在费用重复计入风险控制的问题。接手者必须先处理平台约束或换支持自定义成本的回测环境。
- 用户明确不接受通过“退还/还原固定手续费”的方式伪装平台零手续费；不要偷偷加入这类代码。

## 6. 给接手者的优先迭代建议

1. **数据准确性**：先取得同时间戳、同报价规则的两腿 H1 数据，特别检查 2024-05-20 ETH、2025-01-20 ETH、2025-04-21 BTC 价差异常；不能把 H1/H4 自己合成后的收盘价比较当成独立时间一致性验证。
2. **经济费用与账户权益一致性**：先解决原生交易费/融资与 0.05% 自定义费用的兼容性，再谈评分优化；严格分开 `native_score` 和 `economic_net_pnl`。
3. **放宽过严的交易筛选做消融**：该版本 2025 只有 21 组配对，交易频率评分约 1.70；分别测试 `max_recent_h1_basis_jump`、`max_recent_4h_basis_range`、`min_net_expected_profit_usd`，一次只改一个因素，避免盲目增加交易数量。
4. **BTC/ETH 分别校准**：记录每组胜率、因子、持有时间和止损触发比例，比较差异；不要简单用一套阈值覆盖不同交易品种。
5. **更稳健的执行模型**：检查双腿未同时成交、订单回调缺失、实际 `fill_price`/`fill_volume` 的可靠性，以及流动性和滑点。现货做空借币成本、期货资金费、合约展期都未在当前研究里充分纳入。
6. **研究设计**：保留 2025 基线，测试 2021–2025、2023–2025 作为稳健性，再引入不参与调参的真正留出时间段；每次保存代码 SHA、API 配置、生效配置、原生评分与扣费后收益。
